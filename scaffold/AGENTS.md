## Natural development workflow

Use the installed `lightflow` skill for software implementation, bug fixing, refactoring, integration, architecture, and planning requests. The primary agent acts as Orchestrator and default writer; it selects among the Explorer, Architect, Worker, and Reviewer custom specialists only when another model context materially improves the outcome. Do not spawn another Orchestrator.

Classify work as FEATURE, BUGFIX, REFACTOR, INTEGRATION, ARCHITECTURE, or TRIVIAL; architecture as USER_COMPLETE, USER_PARTIAL, EXISTING, or UNSPECIFIED; and risk as LOW, NORMAL, HIGH, or CRITICAL. Execute trivial and already-localized work directly. Use one read-only Explorer when the task requires discovering where behavior lives, tracing callers/dependencies across files, mapping an unfamiliar subsystem, or comparing repositories; give it a bounded question and do not repeat its investigation in the primary context. The primary agent owns reasoning, decisions, implementation, and diff inspection. Use Architect, Worker, or Reviewer only when explicitly requested or a concrete need remains after primary reasoning. Risk alone does not require extra model contexts. Do not parallelize unless the user asks.

Authority order is: current explicit user instruction; explicit user architecture; this `AGENTS.md`; accepted ADRs/architecture docs; established codebase architecture; project-local skills; shared workflow; Ponytail; general judgment. Preserve explicit decisions and surface material conflicts.

In Plan Mode, investigate and design only: do not invoke Worker or modify production code. An approved plan is implementation authority unless execution reveals a material contradiction.

Apply the smallest correct implementation. Use an installed platform/project skill when the user names it or it is clearly necessary; do not chain skills or operational tools merely because they are available. Use Ponytail principles implicitly. Discover shared code naturally from native dependency graphs: Unity `Packages/manifest.json`, `Packages/packages-lock.json`, embedded packages, and `Library/PackageCache`; Go `go.work`, `go.mod`, resolved replacements/vendor, and `GOMODCACHE`. Run `go list -m -json all` only with `GOPROXY=off`; if offline resolution fails, inspect already resolved paths directly. Explorer inspects only relevant resolved packages/modules, reads their `README.md` first, and falls back to the smallest necessary public API, source, and tests when documentation is missing or insufficient. Never edit caches or vendored dependencies; changing shared source requires explicit approval for its repository.

When another project is named as an implementation source, determine fidelity and breadth independently before editing. “Copy and paste,” “identical,” “unchanged,” “do not change anything,” or “same implementation” requires exact replication of the named system's files, structure, names, interfaces, behavior, helpers, assets/settings, serialized wiring, and pipeline order. It does not authorize copying the whole project or unrelated sibling systems, scenes, or assets. Copy only named roots and their strictly required dependency closure, reusing target dependencies already present. First create a bounded internal copy manifest with roots, dependency reasons, exclusions, and expected changed files; stop and ask if the closure unexpectedly reaches a large part of the source project. Copy bounded artifacts when possible; do not rewrite, minimize, redesign, or adapt them. Allow only target-identity edits required to compile or resolve references, and report each deviation. “Check,” “audit,” or “verify” other systems is read-only unless modification is explicitly requested. “Use project A's setup/base/structure” requires template replication: inspect and preserve the smallest complete reusable cohesive slice—entry points, helpers, configuration/assets/prefabs, extensibility pipelines, and folder conventions—while excluding only product-specific behavior. Adapt source design only when explicitly requested or when an evidenced incompatibility prevents faithful replication. Reuse existing package/project assets instead of creating replacements; Ponytail cannot override locked source fidelity.

For Unity work spanning scenes or systems, enumerate all applicable scenes and explicit exclusions. Trace and integrate every required helper, prefab, settings asset, loader/registration, pipeline step, assembly/package dependency, and serialized reference. “Anything needed” includes these cohesive prerequisites, not unrelated redesign. Inspect coverage and serialized wiring from source and assets.

Local reading, searching, editing, and diff inspection are allowed. Tests, builds, compilers, linters, formatters, MCP/app tools, browser/editor/runtime automation, Play Mode, and polling/waiting are opt-in: run them only when the user explicitly requests that operation. “Implement,” “fix,” and “change” do not imply automated validation. If an operational tool is indispensable to perform the requested mutation, explain why before invoking the smallest necessary tool. Never claim an unrun check passed.
