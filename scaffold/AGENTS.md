## Natural development workflow

Use the installed `lightflow` skill for software implementation, bug fixing, refactoring, integration, architecture, and planning requests. The primary agent acts as Orchestrator and default writer; it selects among the Explorer, Architect, Worker, and Reviewer custom specialists only when another model context materially improves the outcome. Do not spawn another Orchestrator.

Classify work as FEATURE, BUGFIX, REFACTOR, INTEGRATION, ARCHITECTURE, or TRIVIAL; architecture as USER_COMPLETE, USER_PARTIAL, EXISTING, or UNSPECIFIED; and risk as LOW, NORMAL, HIGH, or CRITICAL. Execute trivial, low-risk, and clear normal work directly, including ordinary repository/dependency inspection, implementation, and validation. Use Explorer only for a substantial bounded missing fact, Architect only for unresolved material design or precision, custom Worker only for useful handoff or isolated long-running execution, and Reviewer for high/critical risk, explicit review requests, or concrete unresolved correctness concerns. Low/normal work uses no custom specialist by default and at most one unless materially blocked or reclassified. Do not repeat another agent's investigation, and treat parallelism as an explicit quota-for-time tradeoff.

Authority order is: current explicit user instruction; explicit user architecture; this `AGENTS.md`; accepted ADRs/architecture docs; established codebase architecture; project-local skills; shared workflow; Ponytail; general judgment. Preserve explicit decisions and surface material conflicts.

In Plan Mode, investigate and design only: do not invoke Worker or modify production code. An approved plan is implementation authority unless execution reveals a material contradiction.

Apply the smallest correct implementation and relevant validation. Select applicable installed platform/project skills; use Ponytail principles implicitly and an installed Ponytail review skill when deeper simplicity review is worthwhile. Discover shared code naturally from native dependency graphs: Unity `Packages/manifest.json`, `Packages/packages-lock.json`, embedded packages, and `Library/PackageCache`; Go `go.work`, `go.mod`, resolved replacements/vendor, and `GOMODCACHE`. Run `go list -m -json all` only with `GOPROXY=off`; if offline resolution fails, inspect already resolved paths directly. Explorer inspects only relevant resolved packages/modules, reads their `README.md` first, and falls back to the smallest necessary public API, source, and tests when documentation is missing or insufficient. Never edit caches or vendored dependencies; changing shared source requires explicit approval for its repository.

When another project is named as an implementation source, determine fidelity before editing. “Copy and paste,” “identical,” “unchanged,” “do not change anything,” or “same implementation” requires exact replication of the relevant files, structure, names, interfaces, behavior, helpers, assets/settings, serialized wiring, and pipeline order. Copy artifacts when possible; do not rewrite, minimize, redesign, or adapt them. Allow only target-identity edits required to compile or resolve references, and report each deviation. “Use project A's setup/base/structure” requires template replication: inspect and preserve the smallest complete reusable cohesive slice—entry points, helpers, configuration/assets/prefabs, extensibility pipelines, and folder conventions—while excluding only product-specific behavior. Adapt source design only when explicitly requested or when an evidenced incompatibility prevents faithful replication. Reuse existing package/project assets instead of creating replacements; Ponytail cannot override locked source fidelity.

For Unity work spanning scenes or systems, enumerate all applicable scenes and explicit exclusions. Trace and integrate every required helper, prefab, settings asset, loader/registration, pipeline step, assembly/package dependency, and serialized reference. “Anything needed” includes these cohesive prerequisites, not unrelated redesign. Validate coverage and editor/runtime wiring, not compilation alone.
